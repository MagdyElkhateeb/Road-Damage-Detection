# Road Damage Detection Using YOLO

A computer vision project that **detects and localizes road-surface damage** using object detection. Three small YOLO architectures—**YOLOv8s, YOLO11s, and YOLO26s**—were fine-tuned and evaluated under the same experimental setup. **YOLO26s** achieved the highest validation mAP50-95 and was selected for deployment through a **Gradio** web interface.

## Overview

The project covers dataset acquisition, model training, quantitative comparison, validation, prediction visualization, and an interactive deployment demo. Upload a road image to the Gradio application and see predicted damage bounding boxes, class names, and confidence scores.

### Supported damage classes

The Roboflow dataset used in the notebook contains **7 classes**:

- `alligator`
- `block`
- `crack`
- `edge`
- `longitudinal`
- `pothole`
- `transverse`

Class labels shown by the app are **loaded from the trained `best.pt` checkpoint** rather than hardcoded.

## Model comparison

Validation results recorded in `road-damage-detection.ipynb`:

| Model | mAP50 | mAP50-95 | Precision | Recall | Model size | FPS* |
|:--|--:|--:|--:|--:|--:|--:|
| YOLOv8s | 0.4101 | 0.2399 | 0.6223 | 0.3979 | 21.48 MB | 59.30 |
| YOLO11s | 0.4284 | 0.2529 | 0.6122 | 0.4217 | 18.30 MB | 55.50 |
| **YOLO26s (selected)** | **0.4400** | **0.2578** | **0.6415** | **0.4373** | 19.38 MB | 57.97 |

**Why YOLO26s?** It produced the best mAP50-95 (**25.78%**) as well as the highest mAP50, precision, and recall in this comparison. Its checkpoint is smaller than YOLOv8s and its recorded FPS exceeds YOLO11s. YOLOv8s was slightly faster, and YOLO11s had the smallest file, but YOLO26s offered the best overall validation detection quality.

\* **FPS is benchmark-specific:** The notebook times 20 repeated predictions on a single validation image after one warm-up. This is not a portable, end-to-end production FPS guarantee. The recorded experiments used a Kaggle Tesla T4 GPU.

For a fuller discussion, see [Model_Comparison_Report.pdf](Model_Comparison_Report.pdf).

## Experimental setup

| Setting | Value |
|:--|:--|
| Dataset | Roboflow project `ay7agaa/road-damage-l1ju7-jd0gc`, version 1 |
| Dataset format | YOLO detection (`yolov8` download format) |
| Models | `yolov8s.pt`, `yolo11s.pt`, `yolo26s.pt` |
| Epochs | 50 |
| Batch size | 16 |
| Input image size | 640 × 640 |
| Configured initial learning rate | 0.01 (`lr0`; optimizer set to `auto`) |
| Optimizer | `auto` |
| Random seed | 42 |
| Primary selection metric | Validation mAP50-95 |
| Validation evaluated | 1,142 images, 3,570 annotated instances |

The notebook obtains the dataset through Roboflow with an API key stored in **Kaggle Secrets** under `ROBOFLOW_API_KEY`. Do not commit your API key or the downloaded private dataset to GitHub.

## Run the Gradio app locally

### 1. Prerequisites

- Python 3.11 recommended (use an environment compatible with your installed PyTorch version)
- The fine-tuned `best.pt` file in the project root, beside `app.py`
- An internet connection for the initial package installation

### 2. Create a virtual environment (Windows PowerShell)

```powershell
cd D:\Road-Damage-Detection
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

On Linux/macOS, use `python3 -m venv .venv` and `source .venv/bin/activate` instead.

### 3. Start the application

```bash
python app.py
```

Open the local URL shown in the terminal (normally **http://127.0.0.1:7860**). Upload any supported image (JPG, JPEG, PNG, WEBP, or BMP), adjust the confidence threshold, and click **Detect road damage**. The app displays the annotated image, per-class counts, and a table of detection details.

If `Test Images/` exists, supported images in that folder appear as selectable examples. Sample image names do not need to follow a fixed pattern.

**Missing weights error:** If the app says `Model weights not found`, copy your trained checkpoint to `D:\Road-Damage-Detection\best.pt` and start the app again.

## Notebook workflow

1. Install `roboflow` and `ultralytics`, then import the required libraries.
2. Download Roboflow dataset version 1 using the Kaggle secret.
3. Configure the dataset paths, models, and training hyperparameters.
4. Train each model, load its best checkpoint, and run validation.
5. Record mAP50, mAP50-95, precision, recall, checkpoint size, and FPS.
6. Save results to `outputs/results.json` and comparison plots under `outputs/plots/` in the Kaggle environment.
7. Select the highest-mAP50-95 model and visualize sample validation predictions under `outputs/predictions/`.

Kaggle training outputs such as `experiments/`, `outputs/`, and `dataset/` are **not shown in the local GitHub project screenshot**. They are created inside `/kaggle/working/` when the notebook runs.

## Deployment

The demo uses the **Ultralytics Python API + Gradio**. It loads `best.pt` once when the process starts and performs detection at `imgsz=640` with an adjustable confidence threshold (default `0.25`). The app does not re-train the model.

For a Gradio-based hosting service such as **Hugging Face Spaces**, supply at least `app.py`, `requirements.txt`, and the same fine-tuned `best.pt`, and select the appropriate Gradio runtime. Check that your model and dataset licenses permit the intended type of deployment.

## Limitations

- The results above come from the notebook's **validation set**, not an independently reported real-world test benchmark.
- **mAP50-95 = 0.2578** and **recall = 0.4373** indicate that performance needs improvement before safety-critical operational use.
- Class distribution is uneven: the notebook reports **only one `edge` validation instance**, so that class cannot be considered reliably evaluated.
- The notebook warned about some mixed segmentation/box labels and corrupt images; data quality should be audited before additional training.
- Inference speed depends on image size, hardware, preprocessing, and serving configuration.
